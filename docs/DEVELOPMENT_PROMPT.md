# 产品开发提示词

以下提示词可复制给其他大模型，用于从零实现同类产品。它描述产品目标、架构和验收要求；实际环境中的构建结果以执行记录为准。

```text
你是一名资深全栈工程师。请从零实现“数独学院 Sudoku Academy”，交付完整源码、可运行产品、自动化测试、构建脚本和维护文档。

请实际编写代码、执行测试和构建，不要只输出方案或界面原型。按阶段推进，但最终交付一个完整、可维护、支持离线使用的产品。

一、产品目标

开发一个教学型数独应用，支持：
1. 游玩：生成唯一解题目、填写数字、记录候选数、提示和检查。
2. 构造器：用户创建题目，检查冲突及解的数量。
3. 逐步求解：使用人类逻辑解释每一步，并高亮相关格子和候选数字。
4. 操作回放：还原用户每一步操作后的棋盘。
5. 本地统计：记录完成数量、不同难度成绩、最快和平均用时。
6. 拍照或相册导入：在本机离线识别数独图片。
7. 六语言界面及浅色、深色、护眼三套主题。

支持五个平台：
- Web：完整静态网页，可离线运行。
- Windows：Electron 安装版和便携版。
- Android：WebView 应用及可安装 APK。
- iOS：Capacitor/WKWebView 工程。
- 微信小程序：原生小程序界面，复用共享数独核心。

不需要后端、账户、云端数据库或云端 OCR。

二、源码和输出目录

工作目录只保留两个主要子目录：

project/
├── repo/                   # Git 仓库，只管理源码和必要构建输入
│   ├── README.md
│   ├── LICENSE
│   ├── package.json
│   ├── package-lock.json
│   ├── .gitignore
│   ├── .gitattributes
│   ├── web/                # index.html、styles.css、离线资源
│   ├── src/
│   │   ├── engine/
│   │   ├── generator/
│   │   ├── constructor/
│   │   ├── ocr/
│   │   ├── replay/
│   │   ├── stats/
│   │   ├── ui/
│   │   └── locales/
│   ├── platforms/
│   │   ├── desktop/
│   │   ├── android/
│   │   ├── ios/
│   │   └── wechat/
│   ├── config/
│   ├── scripts/
│   ├── test/
│   └── docs/
└── dist/                   # 最终交付件，不上传源码仓库
    ├── README.md
    ├── web/
    ├── windows/
    ├── android/
    ├── ios/
    ├── wechat/
    └── metadata/
        ├── SHA256SUMS.txt
        └── build-info.json

要求：
- 源码根目录尽量简洁，配置按用途归属。
- 工具强制要求固定位置的配置文件保留在对应工程中。
- 中间文件放入被 Git 忽略的 repo/.build/。
- node_modules、安装包、缓存、日志、密钥和生成副本不得提交 Git。
- dist 必须能够从干净检出的 repo 和明确的工具链重新生成。
- 不允许通过复制历史安装包冒充本次构建。
- 原生二进制不强求跨环境哈希完全一致，但必须记录实际来源。
- 不创建重复配置、无用模板、未引用的旧代码或空占位工程。

三、共享架构

Web、Windows、Android、iOS 共用同一套 HTML/CSS/JavaScript 界面和核心代码。

微信小程序采用 WXML/WXSS/JavaScript 原生视图，但必须复用相同的：
- 棋盘规则和解计数；
- 求解技巧；
- 唯一解生成器；
- 构造器校验；
- OCR 几何处理；
- 回放和统计数据结构；
- 多语言文案。

不要为不同平台分别实现数独算法。

共享 JavaScript 模块应能够在 Node 测试、浏览器和微信环境中使用。
可以采用 UMD/CommonJS 兼容结构。网页离线入口不能依赖外部 CDN 或网络模块加载。

平台资源通过脚本统一生成，并逐文件校验，禁止手工修改生成副本。

四、棋盘和交互

棋盘必须用真实界面元素生成，不能用图片充当可交互棋盘。

Web 使用：
- JavaScript 创建 81 个单元格；
- CSS Grid 排成 9×9；
- 每三行、三列使用加粗边框；
- 单元格内包含数字区域和 1–9 候选数字区域。

界面需要：
- 自适应桌面和手机屏幕；
- 选中格、同行同列同宫、相同数字高亮；
- 冲突、错误和提示状态；
- 给定数字与用户输入的视觉区分；
- 屏幕数字键盘和桌面键盘操作；
- 候选模式、擦除、撤销、重来、暂停、计时；
- 即时显示错误、点击检查时显示、关闭错误提示三种模式；
- 提示、应用提示、显示答案；
- 清楚的加载、失败、完成状态。

主题与语言独立保存。重启后恢复选择。

五、核心数独算法

棋盘使用长度为 81 的行优先数组：
- 0 表示空格；
- 1–9 表示数字；
- 候选数使用 9 位 bitmask。

实现：
- 题面解析和导出；
- 行、列、宫冲突检查；
- 候选计算；
- 解计数，支持最多计数到 2；
- 获取一个完整解；
- 唯一解、多解、无解判断。

回溯可以用于解计数、生成终盘和内部正确性验证。
面向用户展示的逐步求解必须使用真实逻辑技巧，不能把回溯答案包装成逻辑解释。

实现以下 19 种技巧，每种技巧独立模块：

Tier 1：
1. Naked Single
2. Hidden Single

Tier 2：
3. Locked Candidates Pointing
4. Locked Candidates Claiming
5. Naked Pair
6. Hidden Pair

Tier 3：
7. Naked Triple
8. Hidden Triple
9. X-Wing
10. Swordfish
11. Skyscraper
12. Y-Wing
13. XYZ-Wing
14. Two-String Kite

Tier 4：
15. Jellyfish
16. Unique Rectangle
17. Simple Colouring
18. W-Wing
19. XY-Chain

每个技巧返回：
- 技巧标识和等级；
- placements；
- eliminations；
- 高亮格子、候选和单元；
- explainKey；
- 语言中立的 explainVars。

要求：
- 只有能产生实际变化时才返回步骤；
- 落子和排除必须针对合法的当前状态；
- 保留已经完成的候选排除，不能每一步重算时重新加入；
- 求解时由简单到复杂查找下一步；
- 支持步骤回放和任意步骤状态恢复；
- 超出已实现技巧能力时报告停滞；
- Unique Rectangle 只能在允许假设唯一解时使用；
- 为链搜索和总步骤数设置合理上限。

六、生成题目和构造器

生成器：
1. 随机生成合法终盘；
2. 挖洞时逐次检查唯一解；
3. 使用人类逻辑求解器完整求解并评级；
4. 只有满足目标技巧等级的题目才接受。

难度：
- 简单：最高 Tier 1；
- 中等：最高 Tier 2–3；
- 困难：最高 Tier 4。

不能只按已知数字数量划分难度。

支持种子随机数，便于复现测试。
设置尝试次数和时间预算，失败时明确提示重试。

构造器区分：
- 格式错误；
- 冲突；
- 无解；
- 多解；
- 唯一解。

唯一解题目可以转入游戏，并保留候选标记。

七、逐步求解、回放和统计

逐步求解界面：
- 显示技巧名称、等级和当前语言的解释；
- 高亮参与推理和被排除的候选；
- 支持上一步、下一步、滑杆、步骤列表、自动播放；
- 明确显示解出、矛盾或停滞状态。

操作回放：
- 保存初始局面；
- 记录填数、擦除、候选、撤销、提示、显示答案等操作；
- 保存每个动作后的完整棋盘及候选快照；
- 支持 JSON 序列化、持久化和播放；
- 限制历史数量及单局动作数量。

统计：
- 总完成数；
- 各难度完成数；
- 最快和平均用时；
- 最近完成记录；
- 支持重置。

显示答案不能计入成功完成统计。
各平台数据只保存在各自本地，不假装实现跨设备同步。

八、多语言

内置：
- 简体中文 zh-CN
- 繁体中文 zh-Hant
- English en
- 日本語 ja
- Français fr
- Español es

src/locales/*.json 是唯一文案来源。
包括界面、错误信息、技巧名称、求解解释、回放、统计和 OCR 文案。

构建时生成离线 JavaScript 语言包，避免 file:// 下读取 JSON 的限制。

要求：
- 六种语言的键和占位符一致；
- 支持即时切换；
- 选择本地持久化；
- 不在算法中硬编码解释句子；
- 技巧解释用结构化变量和模板生成；
- 新语言注册流程写入文档。

九、离线图片识别

支持：
- 相机拍摄；
- 相册或文件选择；
- 棋盘定位；
- 旋转和透视矫正；
- 81 格裁切与预处理；
- 数字识别；
- 识别结果的规则和唯一解校验。

Web、Windows、Android、iOS 使用本地 Tesseract WASM 和内嵌语言数据。
微信使用纯 JavaScript 模板分类器，复用几何处理和校验逻辑。

图片不得上传服务器。

特别注意：
- 必须实际验证 file:// 离线运行；
- Chromium 可能阻止 Worker 通过 importScripts 加载 file:// 脚本；
- 需要可靠的离线加载方式，例如将 Worker 和 WASM 引导脚本生成到同一个 Blob Worker；
- 不得关闭浏览器安全设置来掩盖加载问题；
- 训练数据可以生成内嵌资源，但原始输入和生成脚本必须保留；
- 第三方兼容补丁需要说明原因；
- 不能静默降级后仍声称 Tesseract 已正常工作；
- 失败要有明确提示，并处理重试、取消、权限拒绝和资源释放。

十、平台交付

Windows：
- Electron x64；
- NSIS 安装版和便携版；
- 启用上下文隔离、关闭 Node 集成；
- 合理配置沙箱、导航限制和相机权限；
- 打包后检查 app.asar 的入口、脚本、样式和 OCR 资源；
- 图标输入必须存在，不能引用缺失文件。

Android：
- WebView 加载本地 Web 资源；
- 处理相机运行时权限、文件选择及必要生命周期行为；
- 本地构建脚本兼容 Windows 和 Linux/macOS；
- 明确 JDK、SDK、Build Tools 版本；
- 生成可安装调试 APK；
- 不提交调试包或私人签名密钥。

iOS：
- 提供完整 Xcode 工程、共享 Scheme 和固定版本 SwiftPM 依赖；
- 配置相机和相册权限说明；
- 交付包含最新 Web 资源的工程；
- 没有 macOS/Xcode 时，不得声称已经编译或运行验证；
- 没有实际生成 IPA 时，不得把工程目录称为 IPA。

微信：
- 提供完整可导入工程；
- 共享核心自动生成；
- 相机和相册 API 有必要的降级处理；
- 真机预览需要用户自己的 AppID；
- 不得声称 Node 模拟测试等于微信真机验收。

十一、构建和测试

提供清晰命令，至少覆盖：
- 安装锁定依赖；
- 运行测试；
- 启动网页和桌面开发模式；
- 同步平台资源；
- 校验同步结果；
- 生成共享交付件；
- 构建 Windows；
- 构建 Android；
- 校验 dist。

测试覆盖：
- 基础规则与解计数；
- 19 个技巧的真实触发和正确动作；
- 与已知完整解逐步对照；
- 三档唯一解生成与评级；
- 构造器各状态；
- 多语言键、占位符和解释；
- 回放序列化和统计；
- 正拍、旋转、透视 OCR 样本；
- 平台工程结构和共享资源一致性。

不要为了达到固定测试数量编写无意义测试。

增加真实浏览器离线 OCR 验收：
1. 禁止 HTTP/HTTPS 网络请求；
2. 先载入另一道有效题目；
3. 导入测试图片；
4. 等待识别真正完成；
5. 检查题面与预期一致；
6. 确认实际使用目标 OCR 后端；
7. 页面错误、Worker 加载错误或非预期降级必须导致测试失败。

清楚区分：
- 单元测试；
- 浏览器交互测试；
- 原生编译；
- 包内容检查；
- 模拟器运行；
- 真机验收。

没有执行过的检查不能写为通过。

十二、文档、清理和最终验收

文档包括：
- 简洁的中英文 README；
- 用户指南；
- 架构说明；
- 技巧说明；
- 多语言维护；
- OCR 资源与限制；
- 构建发布；
- 测试及设备验收；
- 第三方许可。

README 最多保留一张整体界面预览，不堆积截图。
不保留虚构版本历史、失效路径、过期开发报告、无依据的性能数字或已勾选的历史验收清单。

使用 MIT 许可管理自有代码，保留第三方资源各自的许可和必要声明。

最终从仅含 Git 跟踪文件的干净源码验证：
- 依赖能按锁文件安装；
- 生成文件能重新生成；
- 测试通过；
- 当前可用工具链能完成对应平台构建；
- dist 文件清单和哈希校验通过；
- 构建来源记录准确；
- 不依赖旧安装包、隐藏缓存或未提交文件；
- 无明显重复资源、死代码和无用直接依赖。

如果配置 GitHub Actions，应分别使用适合的平台执行构建，说明产物存储与保留策略。
创建仓库、推送、发布和使用账户凭据前，应确认用户授权；不得把凭据写入文件或日志。

最终报告：
1. 实现了哪些功能；
2. 源码和交付件的位置；
3. 启动、测试和构建命令；
4. 实际执行过的验证及结果；
5. 尚未完成的平台运行验收或环境限制；
6. 哪些输出是安装包，哪些只是待编译工程。

不要把界面原型当成完整产品，不要把编译成功当成真机功能全部通过。
```
